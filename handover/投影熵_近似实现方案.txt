==============================================================================
 投影熵（近似/桶近似版）—— 实现方案（沙箱恢复后按此落地）
==============================================================================
 背景：用户要求去掉"黑占比"，改用【列投影熵 + 行投影熵】作为第三/第四特征。
 本文给的是【桶近似】版的完整可行的实现细节（零乘法、0 ERAM、约 480 LUT）。

----------------------------------------------------------------------
 一、数学（避免除法爆炸的等价式）
----------------------------------------------------------------------
   c[x] = 框内第 x 列的图案（暗/二值）像素数      S = Σ c[x]
   H_col = -Σ p log2 p  其中 p = c/S
         = log2(S) - (1/S) · Σ c·log2(c)          <-- 用这个式子
   H_col_norm = H_col / log2(W)

   行同理（把 x 换成 y、W 换成 H）。

   关键：Σ c·log2(c) 用【按量级分桶 + 查常数表】近似，不查 128 项大表、不乘法。

----------------------------------------------------------------------
 二、桶表（已算好，直接用）
----------------------------------------------------------------------
   桶   c 范围      桶内代表值 c·log2(c) 近似常数    怎么算（移位/加法，零乘法）
   b0   0            0                              忽略
   b1   1            0                              （log2(1)=0）
   b2   2..3         3                              2+1
   b3   4..7        14                              8+4+2
   b4   8..15       41                              32+8+1
   b5   16..31     107                              64+32+8+2+1
   b6   32..63     265                              256+8+1
   b7   64..127    628                              512+64+32+16+4

   Σ c·log2(c) ≈ 3·n2 + 14·n3 + 41·n4 + 107·n5 + 265·n6 + 628·n7
   （nX = 落在桶 bX 的列数；n1 贡献 0，n0 忽略）

   桶判定（c 为 7 位）：
     b2: c[6:2]==0 && c!=0 && c!=1           其实直接按位判更快：
     c>=64 -> b7 ; c>=32 -> b6 ; c>=16 -> b5 ; c>=8 -> b4 ;
     c>=4  -> b3 ; c>=2  -> b2 ; else (0/1) 忽略
   → 6 个比较器 + 6 个递增计数器（每个 6 位，最多 96）

----------------------------------------------------------------------
 三、硬件结构（模块 proj_entropy.v，内联进 wrapper 或放 mixer）
----------------------------------------------------------------------
   输入（帧末已算好的投影，来自现有 pb_col[]/pb_row[] 或独立新计数器）：
     · 列计数 c_col[0..NCOL-1]（7 位，NCOL = 内缩后宽 60）
     · 行计数 c_row[0..NROW-1]（7 位，NROW = 内缩后高 96）
     · start（帧末 1 拍）
   串行引擎（一个 FSM，约 250 拍，消隐 9600 拍足够）：
     ① 扫 NCOL 列：分桶 -> n2..n7 累加；同时 S_col 累加（各 13 位）
     ② 算 Σcol = 3n2+14n3+41n4+107n5+265n6+628n7（16 位，移位加法树）
     ③ t_col = Σcol / S_col（复用现有串行减法除法器，最多 100 拍）
        H_col = log2(S_col) - t_col
        log2(S) 用【前导 1 检测 + 4 项尾数微表】近似（S<=5520，13 位）
     ④ h_col100 = H_col × 100 / log2(NCOL)，log2(60)≈5.907 -> 常数 16.93
        → h_col100 ≈ H_col × 17（移位加法：16+1），范围 0..100
     ⑤ 行重复 ①~④（NROW=96，log2(96)≈6.585 -> 常数 15.18 -> ×15 = 16-1）
     ⑥ 输出 h_col100 / h_row100（8 位，0..100）+ done

   ★ 全部常数乘法用移位加法，DSP = 0；不需要 ERAM（表只有 8 个常数）。

----------------------------------------------------------------------
 四、资源估算（桶近似版）
----------------------------------------------------------------------
   投影计数器（7 位 × 156 个，含现有的 6 位加宽）      ~0 LUT / +156 FF
   分桶 + 6 个桶计数器                                ~90 LUT / ~40 FF
   桶权累加（6 个常数乘加，16 位）                    ~70 LUT / ~24 FF
   log2(S)（前导 1 + 尾数微表，2 路复用）             ~90 LUT / ~20 FF
   串行除法（复用 1 个，跑 2 次）                      ~50 LUT / ~40 FF
   FSM/减法/进位                                      ~60 LUT / ~30 FF
   BCD + OSD 一行（E 行：列熵% + 行熵%）              ~120 LUT / ~16 FF
   ------------------------------------------------------------------
   合计                                    约 480 LUT / 约 330 FF / 0 ERAM / 0 DSP

   对照：删掉的黑占比约 130 LUT + 1 个 20 位除法被除数 -> 净增约 350 LUT。
   当前设计 LUT 余量很大（删掉识别/帧差后约剩 4000+），完全放得下。

----------------------------------------------------------------------
 五、OSD 显示（新增 E 行，共 5 行）
----------------------------------------------------------------------
   E 行格式： 'E' + 列熵(2 位十进制，0..100) + 行熵(2 位十进制)
   例： E 4 2 3 5   -> 列投影熵 42%、行投影熵 35%
   含义：数值越小 = 投影越集中（笔画简单/竖线少）；越大 = 分布越散（图案复杂）
