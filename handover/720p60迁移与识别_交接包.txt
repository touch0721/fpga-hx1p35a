第 2 节  ★ PLL 的确切答案（你问的"配置来自哪个文件"）
================================================================================
【文件】  user_source/ip_source/PLL/PLL.v
【内部】  ph1p_phy_pll_wrapper_25a56e5ce2f9（安路 PH1P 物理 PLL 原语）

【当前参数（1080p60）】
    .FIN       ("50.000000000")   ← 参考时钟 = 板上 50 MHz 晶振（I_sys_clk）
    .REFCLK_DIV(1)
    .FBCLK_DIV (2)                ← 反馈取 CLKC0（÷15），所以倍频 = 15x2 = 30
    .CLKC0_DIV (15)   -> 1500/15 = 100.000 MHz   系统时钟
    .CLKC1_DIV (63)   -> 1500/63 =  23.81 MHz    摄像头 MCLK/I2C
    .CLKC4_DIV (10)   -> 1500/10 = 150.000 MHz   HDMI 像素时钟
    .CLKC5_DIV (2)    -> 1500/2  = 750.000 MHz   TMDS 串行（= 像素 x5）
    .LPF_RES(0)  .LPF_CAP(13)  .ICP_CUR(29)       环路滤波器
    => VCO = 1500 MHz（所有输出都从它整数分频）

【720p60 需要】像素 74.25 MHz，TMDS 串行 371.25 MHz

【★ 为什么现有 PLL 给不出来】
    1500 / 74.25  = 20.2020   ★ 非整数，分不出来
    1500 / 371.25 =  4.0404   ★ 非整数，分不出来

    数学上：VCO 必须同时被 74.25 和 371.25 整除
            且 VCO / 50（参考）必须是整数
      74.25 / 50  = 297/200  -> 最小 VCO = 50x200 = 10000 MHz  ★ 不可能
      148.50 / 50 = 297/100  -> 最小 VCO = 50x100 =  5000 MHz  ★ 不可能
      371.25 / 50 = 297/40   -> 最小 VCO = 50x40  =  2000 MHz  ★ 超过原语上限

    ★ 结论：50 MHz 参考 + 整数分频，74.25 / 148.5 / 371.25 一个都做不出来。
      （和 1080p60 想要 148.5 MHz 遇到的是同一个障碍）

【三条出路（按推荐顺序）】
    出路A ★推荐  在 TD 的 PLL IP 向导里【新建一个 PLL】（或复制现有的），
                 打开【小数分频 / Fractional】（原语参数名 PI_FRAC_EN，
                 现在的配置里是 DISABLE），让工具算出分频比。
                 生成后把新 PLL 的像素/串行时钟接到 hdmi_tx，
                 并替换 design_top_wrapper.v 里 u_PLL 的那两路输出。
                 ★ 需要你在 TD GUI 里操作，手写 IP 文件过不了 DRC。

    出路B        换参考时钟到 27 MHz：
                     1485 / 27 = 55      整数
                     1485 / 74.25 = 20   整数
                     1485 / 371.25 = 4   整数
                 ★ 但板上只有 50 MHz 晶振，27 MHz 得另外来（外部晶振或另加 PLL）
                 ★ 而且现有 PLL 也分不出 27 MHz（1500/27 = 55.56 非整数）

    出路C        不改时钟，保持 150 MHz 像素时钟，改用非标 H/V 时序凑 60 fps：
                     150e6 / (H_FrameSize x V_FrameSize) = 60
                     例如 V=800 -> H=3125（整数！）
                 ★ 但这不是标准 720p60，显示器未必认
                 ★ 本工程已经踩过这个坑：把 H_FrameSize 从 2223 改成 2222
                   想凑更准的 60 Hz，结果屏幕直接黑屏，只能回退
                 ➜ ★ 强烈不建议

【补充事实】TMDS 串行时钟必须是像素时钟的 5 倍（HDMI 8b/10b，每像素 10 bit
            分 5 个时钟周期传输）。现在 .CLKC5_DIV(2) / .CLKC4_DIV(10) 就是
            150:750 = 1:5，这个比例改频率时必须保持。

第 3 节  ② MIPI D-PHY 怎么确认（你问的"两个模式速率是否相同"）
================================================================================
D-PHY 是加密 IP，由 TD 管理，RTL 改不了。需要确认的是：
    SC520CS 在 1080p60 和 720p60 两个输出模式下，MIPI 的 lane 速率是否相同。

【怎么查】
  1. 看传感器手册里两个模式的 PLL 寄存器（MIPI 时钟分频那几组）
     —— 720p60 的寄存器表在仓库里：user_source/hdl_source/uics520_cfg/uics520reg_720p60.v
        （模块名 uics520reg_720p60，和文件名一致）
        1080p60 的表在同文件的另一段（模块名 uics520reg_1080p60）
  2. 逐条 diff 两张表里与 PLL/MIPI 时钟相关的寄存器
     · 如果只是降帧率或裁剪窗口 -> MIPI 速率不变 -> D-PHY 不用动
     · 如果改了 PLL -> MIPI 速率变了 -> D-PHY 也要跟着改
  3. 参考现有 D-PHY 配置：user_source/hdl_source/mipi_dphy_rx_ph1p_mipiio_wrapper*
     （当前设计按 1080p60 配的）

【已经知道的旁证】
  design_top_wrapper.v 里有：
      S_mipi_last_line_error <= (S_mipi_line_count != 11'd1080);
  说明设计里已经有一个"每帧行数对不对"的检查，切到 720p60 时这里也要改
  （见第 4 节清单第 5 项）。

第 6 节  ★★ 四条硬性规则（这个工程踩过的坑，务必遵守）
================================================================================
【规则 1】绝不编辑 td_project/*.al
    TD 会用内存里的文件列表覆盖它。要加代码就把模块【内联】进
    design_top_wrapper.v 或 isp/isp_top.v。
    （运行参数请走 TD 的 "More Options"，TD 自己会写进 .al 的
      <RtlProperty>/<PlaceProperty>/<RouteProperty> 和 <UserParams>。）

【规则 2】改了源文件必须重新内联
    · frame_diff_onchip.v  -> 内联进 design_top_wrapper.v
    · tile_recog_onchip.v  -> 跑 sim/inline_tile_recog.py
    · sobel_edge_128.v     -> 跑 sim/inline_sobel.py
    ★ 加/改端口时，改的是【源文件】，不是内联副本！
      isp_top.v 第 676 行起是 sobel_edge_128 的内联副本。
      手改副本有两个后果：下次跑 inline 脚本会被冲掉；漏改 isp_top 包装层的
      端口，TD 综合时报 cannot find port 'XXX' on this module。
    ★ 改完必须跑 sim/check_ports.py（秒级，把漏改端口的错挡在编译之前）

【规则 3】不要擅自改显示时序参数和二值帧差阈值 DIFF_THR
    uivtc 的 H_FrameSize 等参数改过出过事故（2223->2222 直接黑屏）。
    DIFF_THR 是用户指定的值。要"降投票门槛"改 MARGIN，不是改 DIFF_THR。

【规则 4】★★ 算术 `*` 一律手写成移位加法 —— 本器件 DSP 只剩 7 个余量
    器件 PH1P35MDG324：DSP 上限 40，基线已用 33。
    TD 会把 Verilog 的 `*`（★ 包括"乘以常量"）映射成 DSP。实测：识别模块里
    6 个 `*` 就把 DSP 推到 54，布局器直接报
        PHY-7027 model type (DSP) exceed the design limits
        PHY-9002 Placer initialization failed
    （TD 还会附带 PHY-9146/9147/9179 提示，但根因在 7027）
    ★ 同样危险的是"把 ISP 里已经死掉的乘法器引出"：
      引出 s1_cb/s1_cr 会让 rgb_to_ycbcr_4 里 24 个常量乘法器复活，
      DSP 从 33 涨到 49。要色彩信息就取 ISP 的 O_col4（比较器算出的色系码，零乘法）。
    ★ 定位工具：python sim/dsp_by_module.py <门级网表>  按模块列出 DSP 分布

【B. ★★ PLL 的真值源（本轮最大的坑）★★】
  症状：改完 PLL.v 后，clk5 变成 375 MHz ✓ 但 clk2 仍是 150 MHz ✗。
  原因：TD 在编译时会【重新生成】ip_source/PLL/PLL.v（时间戳 = 编译时刻），
        而它是按 ip_source/PLL/.params_PLL.txt 里的
            CLK4_REQUEST_FREQ_DISP : 150.000000
        生成的 —— 只改 PLL.v 会被覆盖掉。
  真相（三个文件当时互相矛盾）：
        Design.xml        74.250000 / DIV 20      <- 一直是对的（原始 720p 的值）
        .m_params_PLL.txt CLKC4_DIV 20            <- 一直是对的
        .params_PLL.txt   150.000000              <- 只有这个是 1080p 升级时改的
  ➜ 解决：把 .params_PLL.txt 的请求频率改成 75.000000 / 375.000000，
          同时把 PLL.v 的分频比与注释一并改掉（三处一致）。
  ➜ 判断方法：编译后看 Clock Summary 里 clk2 是不是 75.000 MHz。
  ➜ 若哪天又出现"只改 RTL 不生效"，先看这个文件的时间戳是不是编译时刻。

【C2'. ★ 顺手修掉的 clk2 时序回归（这轮真正把 clk2 拖负的原因）】
----------------------------------------------------------------------------
· 症状：加上 P/G 两行 OSD 后，综合级 clk2（HDMI_PIXEL 75 MHz）SWNS 掉到
        **-0.681 ns / 24 条违规端点**（clk5、clk0 都是正的）。
· 原因：双 dabble（12 位二进制 -> BCD）是很长的组合链，而 hdmi_mixer 的 OSD 是
        纯组合路径：I_tr_* -> bcd4 -> 7 选 1 -> 字符 ROM -> 像素 -> O_hdmi_data。
        原来只有 2 个这样的转换（F/M 行），这次一口气加到 6 个。
· 修法：把这几个 BCD 值【先寄存一拍】再进 OSD 多路器（输入全是准静态、每帧才变一次，
        寄存零代价，只多 64 个 FF）。同时删掉已无消费者的 I_disp_h/I_disp_d 两个转换。
· 实测：clk2 SWNS -0.681 -> **+0.084 ns，0 违规**；mixer 只从 630 LUT 涨到 638 LUT。
· ★ 教训：**凡是要挂到 OSD/像素路径上的"长组合链"（BCD、除法、大比较树），一律先寄存**。

【E. 本轮踩到的 RTL 坑（改这块务必先看）】
----------------------------------------------------------------------------
1. 位图/投影的清零必须放在连通域扫描【之后】。放前面（G_IDLE）会让 CCL 只看到一张空图
   —— 表现是 dots/bars/cells 全 0，而位图在仿真里明明有内容。
2. 合并/重标号必须用"本格被占据"门控。空格子的左上/上右邻居会同时非零，
   不门控就会把两根竹条并成一根（实测五条数成 1 块、maxc = 123）。
3. "新标签"那一拍不能拿 min_nz4 的缺省值 15 当标签用（15 只是"四个候选全 0"的哨兵），
   否则新块的 +1 会记到 15 号标签上 -> 每块都少 1 格、还多出一个假连通块
   （实测四筒数成 5 块、每块 8 格）。
4. ★★ **对参数做部分选择会得到 x**：`NSLOT[3:0]`（NSLOT 是 integer 参数）与
   `LAB_MAX[4:0]`（LAB_MAX 是 4 位参数）都会得到 x —— 前者让 sel_i 恒为 0
   （整个模块一直按 0 号槽工作、TB 里三个槽的特征全一样），后者让 G_STAT 的
   退出条件永远不成立（计数 FSM 死循环、仿真里 gdone 一直是 0）。
   ➜ 要用就先 localparam 定宽：`localparam [3:0] SLOTMAX = NSLOT - 1;` /
     `localparam [4:0] LABMAX5 = LAB_MAX;` 再比较。**iverilog 不报错，只是静默失效。**
5. 长组合链不能挂在 OSD/像素路径上（见 C2' 段）：双 dabble 先寄存，clk2 就从 -0.681 转正。
