### 4. 与手册/工厂表不一致项（本任务要处理的问题）

按置信度分三档。P0/P1 本轮落地，P2 仅上报待 SC520CS 专属资料确认。

**P0 — 增益寄存器映射错误（高置信度，已双重佐证）**

| 证据 | 内容 |
| --- | --- |
| 手册 表 2-3 | `0x3e08`=ANA GAIN，`0x3e09`=ANA FINE GAIN（两者作用不同） |
| 手册 表 2-4 | `0x3e09` 合法值仅 0x20~0x3F |
| SC500 工厂 720p60 表 idx112-113 | `0x3e08=0x0f`、`0x3e09=0x20`，注释 "about 4x analog gain"，与表 2-4 "4.000x" 行严格吻合 |
| SC500 工厂 AE 表 | `3:{16'h3e08, I_AG[15:8]}`、`4:{16'h3e09, I_AG[7:0]}` |
| SC500GainTbl | 输出 16'h0320→033F / 0720→073F / 0F20→0F29，即 `{ANA GAIN, ANA FINE GAIN}`，逐行对应表 2-4 |

当前 SC520CS 实现：

- `SC520GainTbl.v` 输出 `O[23:16]` ∈ {0x00,0x08,0x09,0x0B,0x0F,0x1F}，注释却写 "0x3e09 analog coarse gain"
- `uics520regAE.v`：`0x3e09 ← I_AG[23:16]`（粗调写进了细调寄存器）、`0x3e06 ← I_AG[15:8]`、
  `0x3e07 ← I_AG[7:0]`，而 **`0x3e08` 从未被任何表写入**
- `uics520reg_720p60.v` idx106：`0x3e09 = 0x00`（表 2-4 中无此合法值）

后果：粗调值 {0x00,0x08,0x09,0x0B} 不在表 2-4 合法集合内，ANA GAIN 保持复位默认，
`ae_set.v` 声称的 "144→16 倍模拟增益" 实际无法达成，有效增益显著低于设计意图。

**P0-b — AGC 未使能（高置信度，手册明文要求）**

手册 2.2.3 节：*"将寄存器 16'h3e03 的 Bit[3:0] 设置为 4'hb"*。当前 SC520CS 与 SC500 工厂
720p60 表**均未写 `0x3e03`**。

若 SC520CS 复位默认不是 4'hb，则 `0x3e08/0x3e09/0x3e06/0x3e07` 全部不生效，初始化曝光/增益
与逐帧 AE 写入都会落空，Sensor 停在自身上电默认值。已按手册在初始化表**补写 `0x3e03=0x0b`**
（置于 stream on 之前，索引 164，`REG_SIZE` 165→166），使 P0 的增益修复真正生效。

### 5. 关于提供的 .ini 文件（已排除直接套用）

逐寄存器比对结论（96 项 vs 165 项）：

- 交集仅 28 项，其中**同值仅 3 项**（`0x0103`、`0x3202`、`0x3213`）
- 相差 25 项，包括分辨率、PLL、曝光、增益、时序全部关键寄存器
- 该 ini：1280x1024、RAW8、27 MHz、2-Lane 388.8 Mbps、SlaveID 7-bit 0x30（8-bit **0x60**）
- SC500CS 手册表 1-4 只定义 SID 低→7'h36、SID 高→7'h10，**7'h30 不在其中**
- SC500CS 表 1-7 的 HD 模式是 1280x**720**@60，与该 ini 的 1280x**1024** 不同

**结论：该 ini 既非 SC520CS 配置，也非 SC500CS 标准配置，不可按值搬迁。**
其可用价值仅在 I2C 序列的**结构**：`0x0103=1 → 0x0100=0 → PLL 配置 → … → 0x0100=1`
（先软复位、再显式停流、配置完再开流），当前 SC520CS 表恰好省略了中间的显式停流。

### 6. 第二轮手册核验（新增证据，修正第一轮的推测）

在第一轮基础上把手册页 18~31 与工程 SDC 全部读完，得到以下可定论的事实：

**(1) MIPI 速率已确认是 828 Mbps/Lane — 第一轮的"可能只有 480"推测作废**

工程 SDC（`td_project/camera_to_dsi_display.sdc:2`，本地与官方 ex2 完全一致）声明：

```
create_clock -name {mipi_rx_ck_pad} -period 2.415 -waveform {0.000 1.208} [get_nets {IO_rx_clk_pad_p}]
```

MIPI D-PHY 数据为 DDR（双边沿），故 Lane 速率 = 2 × 1/2.415 ns = 2 × 414.1 MHz = **828.2 Mbps**，
与代码注释 "828 Mbps/Lane" 精确吻合。**代码注释是对的；SC500 工厂表的 "480 Mbps/Lane" 属另一颗
sensor（其 HTS=1600），不可移植到 SC520CS。**

**(2) 手册 2.5 帧率公式给出 HTS 的硬约束**

- 手册 2.5：*"一行时间 = 1/(帧率 × 帧长)"*
- 手册表 2-9：帧长(VTS) = `{0x326d[6:0], 0x320e, 0x320f}`，**默认 24'h07d0 = 2000**
- 手册表 1-7：最高速率 2592×1944@30fps（即默认 VTS=2000 → 30 fps）
- SC520CS 表把 VTS 改写为 0x03e8 = **1000** → 帧率翻倍到 **60 fps**（两种 VTS 下
  `1/(fps×VTS)` 都是 **16.667 μs**，即行周期不变）

因此在 828 Mbps/Lane（像素率 = 828×2/10 = 165.6 Mpix/s）下：

```
HTS = 像素率 × 行周期 = 165.6 MHz × 16.667 μs ≈ 2760
```

**可测预言**：若上板实测 MIPI 为 828 Mbps，则帧率要达 60 fps，sensor 的 HTS 必须约 2760；
若实测帧率约 103 fps，说明 HTS 实际是 SC500 那样的 1600（配置不匹配）。这是**闭合"帧率/行时间"
待确认项**的最小实验。

**(3) 手册文档化覆盖率极低 —— 说明为何 P2 无法从公开手册闭环**

手册全篇出现的 `16'hXXXX` 地址仅 **41 个**（含默认值字面量），而 SC520CS 表写入 **165 个**唯一寄存器，
其中**仅 19 个**在手册中有定义（约 12%）：

| 已文档化且 SC520CS 有写 | 地址 |
| --- | --- |
| 流/复位 | `0x0100`、`0x0103` |
| 输出窗口 | `0x3208`、`0x3209`、`0x320a`、`0x320b` |
| 窗口起始 | `0x3210`、`0x3211`、`0x3212`、`0x3213` |
| 帧长 | `0x320e`、`0x320f` |
| RB Rows | `0x3230`、`0x3231` |
| Slave mode | `0x3222` |
| 曝光/增益 | `0x3e01`、`0x3e02`、`0x3e03`、`0x3e09` |

其余 **146 个**（含 PLL、MIPI 时序补偿、暗电流/坏点、镜头阴影等校准表）均为原厂内部寄存器，
公开手册不予披露。**这就是 P2 清单必须靠 SC520CS 专属资料或 FAE 才能闭环的根本原因**，
不是本轮分析不够深入。

**(4) 手册表 2-1 解决了两项 P2**

- `0x3230`/`0x3231` = RB Rows 低位（`{0x326f[6:0],0x3230,0x3231}`，默认 24'h0004）。
  SC520CS 写 4 = 默认值 → **无需修改**（列 `0x3230`/`0x3231` 项已闭合）。
  附带得到帧结构关系：`Active Rows + Blank Rows = VTS - RB Rows` = 1000-4 = 996，
  其中 720 为有效行、276 为消隐行，自洽。
- `0x3016` = GPIO OEN（Bit[4]，默认 0x00 = GPIO 输入）。SC520CS 已写 `0x3222=0x00`（master 模式），
  master 下 GPIO 不需要输出 → **不写 0x3016 是正确的**（不应照抄 SC500 的 0x10）。

**(5) 手册表 1-9 提供了上板 MIPI 眼图的调试旋钮（当前全依赖默认，正确）**

| 功能 | 地址 | 默认 | SC520CS |
| --- | --- | --- | --- |
| MIPI lane 数 | `0x3018` | 0x3a（Bit[7:5]=3'h1 → 2 lane） | 未写，符合需求 |
| MIPI 位宽 | `0x3031` | 0x0a（5'hA → raw10） | 未写，符合需求 |
| PHY 位宽 | `0x3037` | 0x60（Bit[6:5]=2'h3 → 16bit） | 未写，符合需求 |
| MIPI LP 驱动 | `0x3650` | 0x31（Bit[1:0] 驱动能力） | 未写 |
| Lane0/1 延时 | `0x3652` | 0x00（Bit[3:0] lane0、Bit[7:4] lane1，40 ps/step） | 未写 |
| Clock 延时 | `0x3654` | 0x00（Bit[3] 反向、Bit[2:0] 延时 40 ps/step） | 未写 |

`0x3650`/`0x3652`/`0x3654` 是**唯一可用的 MIPI 采样相位调试手段**：若上板 MIPI 出图有
花屏/闪点，可在这三个寄存器上按 40 ps 步进扫相位，无需改 FPGA 侧。建议写入调试清单。

**(6) 测试图与镜像已确认关闭**

- 表 2-10：`0x4501` 默认 0xb4（Bit[3]=0 → 正常图像）；写 0xbc 才开灰度渐变测试图。
  SC520CS **未写 `0x4501`** → 测试图关闭 ✓（两表一致）。
- 表 2-7：`0x3221` 默认 0x00（Bit[2:1] mirror off、Bit[6:5] flip off）。SC520CS 未写 → 关闭 ✓。
- `0x4509`（SC520CS 写 0x28）**未文档化**，但 SC500 工厂表写同值 0x28 → 属厂商约定，低风险。

**(7) PLL 确实无法校验**

手册 1.8 节只给出 PLL 结构与频率范围（EXTCLK 6~40 MHz、VCO 800~1500 MHz），
并明确*"具体调试说明请咨询 FAE"*，**没有 PLL 寄存器表**。因此 `0x36e9/0x37f9/0x36ea`
等 20 余个 PLL 寄存器只能依赖原厂序列，本轮保持原值。

## Hardware Dependency

`hw_dependency: partial`

理由：本任务主体是**传感器侧 I2C 寄存器配置**（纯 RTL 常量表 + 状态机参数），不涉及 FPGA 引脚
约束或 IOSTANDARD，因此不需要 `fpga-xdc-gen`。但以下两点依赖真实板级/器件事实：

1. `P2` 清单中的 `0x302d`、HTS(`0x320c/0x320d`)、`0x3220`、`0x3812` 等需要**SC520CS 专属资料
   或 FAE**给出取值，不能从 SC500CS 公开手册推导（手册仅文档化全篇 41 个地址）
2. 帧率/行时间的最终确认需要上板实测：MIPI 速率已由 SDC 确认为 828 Mbps，但 sensor 实际 HTS
   未知（未文档化），需实测帧率来反推（预期 60 fps；若为约 103 fps 则 HTS=1600，配置不匹配）

`doc/hw/config.json` 已存在且为 `complete`（PH1P35MDG324 / SC520CS 板卡），但其中的资料是
板级/FPGA 相关资料，**不含 SC520CS 传感器寄存器手册**。

## Acceptance Criteria

1. **AC1（P0）**：`uics520regAE.v` 输出的写序列中，模拟增益粗调写入地址为 `0x3e08`、细调写入
   地址为 `0x3e09`，且写出的 `0x3e09` 值恒落在 0x20~0x3F 区间内。
2. **AC2（P0）**：`SC520GainTbl.v` 在 `I_AG` 从 16 增到 176 的过程中，输出对应的
   `(0x3e08, 0x3e09)` 组合逐点落在手册表 2-4 的合法行内；`I_AG=144` 时增益值达到约 15.75x~16x。
3. **AC3（P0）**：`uics520reg_720p60.v` 初始化表中 `0x3e09` 的写入值为表 2-4 合法值。
4. **AC4（P1）**：`ae_set.v` 曝光上限与初始化表曝光初值均为 1990 = 2*VTS-10，不再出现 1991。
5. **AC5（P2 上报）**：`doc/intake/summary.md` 中 P2 清单完整列出所有"手册可判定语义但取值
   需 SC520CS 专属资料"的寄存器，并注明各自的手册依据与 SC500 工厂参照值。
6. **AC6（不变式）**：`uicfgcs520.v` 的状态机（ID 校验、1 ms/5 ms 上电等待、AE 表切换、
   `0x3812` 打包顺序）保持行为不变；仅允许 `gain_value` 位宽随之调整。
7. **AC7（不变式）**：I2C 从机地址保持 0x6C；Sensor ID 校验值保持 {0xEE4B, 0x9E4B}。
8. **AC8（P0-b）**：`uics520reg_720p60.v` 初始化序列中存在 `0x3e03=0x0b` 写入，且该写入出现在
   `0x0100=0x01`（stream on）之前；`REG_SIZE` 与表内索引连续一致（166 项，0~165 无缺口）。
9. **AC9（不变式）**：初始化序列仍以 `0x0103=0x01`（软复位）为首项、以 `0x0100=0x01`
   （stream on）为末项。
10. **AC10（P2 闭合）**：`0x3230`/`0x3231`（RB Rows）保持 4（= 手册默认 24'h0004）；
    `0x3218`/`0x3031`/`0x3037` 保持不写（依赖默认的 2-lane/raw10/16-bit）；
    `0x3016` 保持不写（master 模式下 GPIO 输入）；`0x4501`/`0x3221` 保持不写（测试图/镜像关闭）。
11. **AC11（不变式）**：MIPI 目标速率保持 828 Mbps/Lane，**不得**引入 SC500 工厂表的
    `0x320c=0x06`/`0x320d=0x40`（HTS=1600，属 480 Mbps 的另一颗 sensor）。
